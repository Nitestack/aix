## Commands

The wrapper is generated by `pkgs.writeShellApplication` and installed as a single `aix` binary.

| Invocation | Behavior |
|---|---|
| `aix claude [profile] [-- args...]` | Set env vars, exec `claude "$@"` |
| `aix pi [profile] [-- args...]` | Set env vars, exec `pi "$@"` |
| `aix shell [profile] [-- command...]` | Set env vars, exec command or launch `$SHELL` / `nu` / `sh` |
| `aix env [profile] [--format sh\|json]` | Print env vars to stdout in the requested format |
| `aix help` / `aix -h` / `aix --help` | Show styled help text and exit 0 |
| `aix` (no args) | Print help to stderr and exit 2 |
| `aix <unknown>` | Print "unsupported target" to stderr, then help, exit 2 |

## Profile behavior

Profiles are a fixed list baked into the script at Nix build time:

```
p   adp   swtb   p-t
```

(Defined in `configurations/nixos/wslstation/sops.nix` as the `profiles` list.)

**Profile selection rules:**

1. If a profile name is given as the second positional argument it is used directly (validated against the baked-in list).
2. If no profile is given and both `stdin` and `stdout` are a TTY, `gum choose` is shown with the available profiles.
3. If no profile is given and there is no interactive terminal, the script exits 1.

**Display labels:** Each profile may have a human-readable label stored at  
`/run/secrets/aix/<profile>-label`.  
`gum choose` shows the label text; if the file is absent the profile name is used as the label.  
Duplicate labels are detected and cause exit 1.

## Environment variables

All five variables are set unconditionally before launching any subcommand.

| Variable | Value | Source |
|---|---|---|
| `AIX_PROFILE` | Selected profile name (e.g. `p`) | Positional arg or `gum choose` |
| `AIX_API_KEY` | API key for the selected profile | `/run/secrets/aix/<profile>` |
| `AIX_BASE_URL` | Shared gateway base URL | `/run/secrets/aix/base-url` |
| `ANTHROPIC_API_KEY` | Same value as `AIX_API_KEY` | Alias for Claude CLI compatibility |
| `ANTHROPIC_BASE_URL` | Same value as `AIX_BASE_URL` | Alias for Claude CLI compatibility |

`ANTHROPIC_*` aliases are set so that `claude` and other tools that consume the standard Anthropic SDK env vars work without modification against the LiteLLM gateway.

## Secret paths at runtime

All secrets are managed by `sops-nix` and decrypted to `/run/secrets/` at boot.  
Owner: the configured user. Mode: `0400`.

| Runtime path | sops YAML key | Contents |
|---|---|---|
| `/run/secrets/aix/<profile>` | `aix/<profile>/key` | API key (no trailing newline after `tr -d '\n'`) |
| `/run/secrets/aix/<profile>-label` | `aix/<profile>/label` | Display label (optional) |
| `/run/secrets/aix/base-url` | `aix/base_url` | Gateway base URL |

Note the key mismatch: the YAML key uses `base_url` (underscore) but the runtime path is `base-url` (hyphen).

The sops secrets file is at `configurations/nixos/wslstation/secrets/aix.yaml` (age-encrypted, key from `~/.ssh/id_ed25519`).

## LiteLLM gateway

The gateway is a **LiteLLM proxy**. The Rust CLI must treat it as an OpenAI/Anthropic-compatible LiteLLM-style endpoint, not as a direct Anthropic API.

Evidence:
- `AIX_BASE_URL` points to the LiteLLM gateway, not `api.anthropic.com`.
- `pi`'s `work-hub` provider (`work-hub.nix`) uses `api = "anthropic-messages"` — the Anthropic Messages API format — but targets the gateway URL from `AIX_BASE_URL`.
- `ANTHROPIC_BASE_URL` is set to the same gateway URL so `claude` CLI redirects its requests there.

## Nix coupling

- The valid profile list is interpolated into the shell script via `lib.concatMapStringsSep` and `lib.concatStringsSep` at build time. Adding or removing a profile requires a NixOS rebuild.
- The home module (`aix.nix`) reads `osConfig.wslstation.aix` — it is tightly coupled to the NixOS `wslstation` module defined in `sops.nix`. It cannot be used standalone without that NixOS module.
- `aix` is included only in the WSL home configuration (`configurations/home/wsl.nix`).
- Runtime tools: `coreutils`, `gum`, `gnugrep`, `gnused` — all pinned via `runtimeInputs`.

## Known bugs and suspicious behavior

### 1. `env --format json` is broken (heredoc quoting)

```sh
cat <<'__AIX_ENV_JSON__'
{"AIX_PROFILE":"$(printf '%s' "$profile" ...
__AIX_ENV_JSON__
```

The single-quoted heredoc delimiter (`'__AIX_ENV_JSON__'`) suppresses all shell expansion. The output is the literal template string — `$(printf '%s' "$profile" ...)` — not the evaluated values. The JSON format has never worked correctly.

### 2. Shell detection order in `shell` command

```sh
if [ -n "${NU_VERSION:-}" ]; then
  shell_cmd="$(command -v nu)"
elif [ -z "$shell_cmd" ]; then   # shell_cmd = $SHELL at this point
  shell_cmd="$(command -v sh)"
fi
```

If the user is inside a nushell session (`NU_VERSION` is set), `nu` is used even if `$SHELL` points elsewhere. This is intentional for nushell users but could surprise users who set `SHELL=fish` while nushell is the parent process.

### 3. `env_format` validated late

`--format` is parsed into `env_format` during argument processing but is only validated inside `emit_env` (after `choose_profile` runs). An invalid format triggers an interactive profile picker before failing, which is wasteful.

### 4. No validation that secrets are non-empty

The script checks that secret files are readable (`[ -r "$key_path" ]`) but does not verify their contents are non-empty. A zero-byte secret file produces an empty `AIX_API_KEY` with no error message.
